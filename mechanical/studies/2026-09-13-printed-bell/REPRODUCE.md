# Reproduce the separate September 13 package

Run from `C:\Projects\dcuccia\digital-handbell`. FreeCAD 1.1.3 is the
exercised console; each report records actual FreeCAD/OpenCASCADE/Python
versions. Ordinary launcher Python needs no FreeCAD modules or extra package.

## Current exact all-front bind

```powershell
python .\tools\build_printed_bell.py --placement .\hardware\handbell\iterations\printed-bell-front\placement-manifest.json
python .\tools\check_printed_bell.py
```

This writes the current assembly to the study root. The completed stage-1
manifest begins `71071718`; the PCB begins `17dc83ce`. Full hashes are in
README, `fit-report.json` and `artifact-manifest.json`.
After copper-only routing changes, the parent must supply the regenerated
manifest with actual new PCB hash and repeat the complete bind. Geometry
can remain unchanged; a stale input hash is still not an approved release.

## Optional explicit development reproduction

```powershell
python .\tools\build_printed_bell.py
python .\tools\check_printed_bell.py --development
```

This writes only `mechanical\studies\2026-09-13-printed-bell\development`.
It reads frozen T8 native/placement/contact/report artifacts without editing
them, translates retained hardware +10.75 mm and keeps the old mixed-face
population visibly and machine-readably marked as **development**.

The automation takes an explicit `--placement` path and does not ask questions.
Final mode writes the study root, not the preserved T8 or electrical directories.
An optional `--output` must remain inside this September 13 study.
Use `--freecad-cmd` for a nondefault installed console path:

```powershell
python .\tools\build_printed_bell.py --freecad-cmd "$env:LOCALAPPDATA\Programs\FreeCAD 1.1\bin\FreeCADCmd.exe"
```

Final mode rejects previews, any electronic B-side population beyond BT1/BT2,
PCB F/B or mount changes, USB-source changes and altered contact geometry.
It accepts D43/46/48 only, so a larger board is an explicit electrical
tradeoff rather than silent generator growth. The authoritative outline is
the supplied polygon, not an ideal replacement circle.

Final source integrity covers actual PCB/schematic bytes, companion hash,
available source symbol/footprint libraries, exact design-input bytes,
preserved BRep/report inputs, and helper/builder/checker code. Text inputs
are embedded as raw base64 in native; binary frozen-native provenance is
recorded by SHA256 and read-only source path. Public paths are
repository-relative, not private session paths.

## Geometry and validation

The source contains original cubic Bezier radial/z poles for shell exterior,
independent cavity and black handle. Alter only this new builder/package,
never the preserved T8 generators/native or shared electrical outputs.
Current inner/outer coordinates are not a constant-normal-offset promise.
The T8 yoke/cradle/cover and thin metal contacts are copied as BReps, not
regenerated by the old builder. Yoke/cradle/contact geometry remains unchanged.
The new cover receives straight spring-tip service channels and added outside
stock with actual external-wall containment witnesses; the full-contact
removal check exposed this omission in the earlier cell/cradle-only screen.

The builder performs:

- One-solid validity for all six structural prints, complete placed-part
  material intersections and explicit service poses.
- Closed cosmetic shell-joint stock:1mm positive offsets of every actual
  nut pocket, inward slot and screw bore contained in the unchanged outer
  solid; matching expanded-cavity containment in the affected band;
  actual3.7mm bearing-floor/2.6mm roof witnesses; zero missing cosmetic
  side-surface area except USB. Static overlap checks alone do not prove this.
- Front shell-screw and driver paths, inward nut loading and complete
  cartridge withdrawal with the shell nuts still installed. The revised
  three-joint pattern is R26.5 at90/210/330 degrees, not the PCB mount pattern.
- Actual USB skin/frame containment and front-face opening equality:
  the14.4x7x1mm locally raised frame at y-29.1..-28.1 retains only the
  intended9.2x3.1mm aperture. The source PCB tongue's full front projection
  is covered by real material. Plane separation proves open-top PCBA
  loading relative to the new skin for every Z position; the full unselected
  nose's continuous straight approach sweep clears shell and carrier.
- B-side label sight columns against the retained cradle, installed cell,
  contacts and remaining hardware with cover/screws removed. These are
  proposed rectangular text reservations, not actual routed-PCB glyphs;
  the builder does not read or edit the active routing source.
- Actual 1.08 mm under-cell section and constructive containment of the
  M4 washer bearing annulus in the real shell.
- Separate supplier-table M4x16 tolerance BReps: maximum head H3.25 and
  washer H1.1, minimum/maximum screw lengths, nut-height coverage, maximum
  tip clearance and empty-shell installation. These are supplier tables,
  not inspected ISO primary standards or certified thread/preload behavior.
- Native reopen and BRep symmetric-difference comparison.
- All full/component STEP exports **before tessellation**, followed by
  per-solid BRep symmetric differences, solid-count/unit/bounds checks.
- Reimport of every released STL as a closed, single-connected,
  non-self-intersecting mesh and reconstructed valid BRep.
- Exact input hashes before/after generation, output hashes and a fresh
  completion token. A console zero exit or stale native file is not success.

The full native/STEP PCBA retains both thin contacts. The inert PCBA STEP/STL
is explicitly contact-free because the frozen contact fold roots have known
mesh limitations; no fabricated bridge is added to metal.

The checker validates all recorded outputs, current inputs, raw native source
records, geometry findings, service poses and final/development scope.
It is not an independent CAD solver; regenerate with FreeCAD for new Boolean
results. Passing it does not qualify printing, force/torque, thermal behavior,
USB mating, actual cell contact, live-cell use or child suitability.

The console runs synchronously, using a uniquely named preference/marker
directory **inside this study** and removing that directory afterward.
No operating-system temporary directory, GUI launch, add-on, package install
or old-generator invocation is required. `freecad-build.log` is diagnostic
console output. STEP/native files left after a failed run are not reviewable;
`review-status.json` and the matching completion/inventory bind are required.
