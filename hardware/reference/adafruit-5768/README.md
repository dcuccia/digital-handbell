# Adafruit 5768 reference: EAGLE sources and KiCad conversion

**Reference only: not a custom digital-handbell schematic or fabrication
package.** No intentional circuit reduction or sensor substitution has been
made. The imported reference is not yet fully reviewed or ERC-clean.

## Initial import evidence

The GUI conversion produced saved native files and project-relative library
references. Native schematic XML-netlist and PDF export succeeded. The
schematic export contains 77 component entries and 78 nets, including additional
unconnected-pin nets generated by KiCad.

Electrical partition comparison used the original EAGLE board's physical
`contactref` element/pad groups and the converted schematic's exported
reference/pin groups. It found **71 matching nonempty signal groups, with no
group-membership differences**, after the following importer renames:

| EAGLE reference | KiCad reference |
|---|---|
| `CHG` | `CHG0` |
| `CHG_EN` | `CHG_EN0` |
| `GAIN` | `GAIN0` |
| `L` | `L0` |
| `OUTPUTS` | `OUTPUTS0` |
| `SERVO` | `SERVO0` |

These names were also observed in the imported PCB. Three additional upstream
board signals have no contact references and were excluded, not treated as
connected nets: `PB22/I6/SERCOM5.2`, `PB23/I7/SERCOM5.3`, and
`PB03/I3/AIN11/SERCOM5.1`.

This comparison checks preservation of the populated source connection groups.
It is not full schematic-to-board synchronization, a package/pad review,
confirmation of unrouted geometry, or functional verification.

## Known conversion findings

The [initial ERC report](reports/reference-erc.json) has **50 findings**:

| Severity/type | Count | Disposition |
|---|---:|---|
| Error: power pin not driven | 8 | Review source power intent and KiCad pin types/power flags |
| Error: pin not connected | 5 | Review intended NC pins versus missing connections |
| Warning: isolated pin label | 2 | Inspect imported label attachment and intended net |
| Warning: unconnected wire endpoint | 35 | Inspect import geometry and dangling source stubs |

Do not blanket-exclude these or assume they are all harmless. No changes were
made merely to obtain a clean ERC result.

A separate CLI PCB-import experiment logged eight skipped package polygons on
EAGLE layers `Route2` and `Route15`. The source board's active layer setup is
`(1*16)`; those two layers are explicitly inactive, and its actual signal
polygons are on layers 1 and 16. The skipped polygons are library-package
content, not evidence that an active four-layer design was flattened.
Nevertheless, review their intended role and compare geometry before treating
any PCB conversion as fabrication-equivalent. The CLI JSON report had empty
warning/error arrays despite the console diagnostics: retain this distinction.
